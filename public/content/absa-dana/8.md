Prosedur membagi dataset menjadi data latih (*training set*), data validasi (*validation set*), dan data uji (*test set*) sering dianggap sebagai tugas rutin yang cukup dipanggil menggunakan satu baris fungsi `train_test_split()` di Python.

Namun, pada dataset Aspect-Based Sentiment Analysis (ABSA), pemanggilan pembagian acak biasa seperti `train_test_split()` adalah **sebuah kesalahan fatal yang akan menghancurkan validitas seluruh eksperimen skripsi!**

Mengapa? Karena terdapat bahaya terselubung yang disebut **Data Leakage (Kebocoran Data)**.

---

## 1. Bagaimana Data Leakage Bisa Terjadi pada ABSA?

Mari kita ingat kembali karakteristik dataset ABSA kita dari Seri 1: **satu ulasan mentah Play Store yang sama bisa menghasilkan lebih dari satu pasangan aspek-sentimen**.

Misalkan kita memiliki satu ulasan pengguna dengan ID ulasan `REV_402`:
> **Isi Teks Ulasan `REV_402`:** *"Fitur transfer bank DANA sangat cepat dan tanpa admin, tapi sayang aplikasi sering keluarsendiri kalau buka menu promo."*

Ulasan ini menghasilkan **dua baris sampel data** dalam dataset kita:
1. Baris A: `(review_id: REV_402, Aspek: Fitur_dan_layanan, Sentimen: Positif)`
2. Baris B: `(review_id: REV_402, Aspek: Teknis_aplikasi, Sentimen: Negatif)`

Perhatikan bahwa kedua baris sampel di atas berasal dari **teks kalimat yang persis sama**.

### Skenario Fatal `train_test_split` Acak Biasa:
Jika kita membagi 1.205 baris data secara acak tanpa memperhatikan `review_id`:
* Baris A (`REV_402`) bisa terlempar ke **Training Set**.
* Baris B (`REV_402`) bisa terlempar ke **Test Set**.

Jika ini terjadi, saat model IndoBERT diuji pada Test Set, model sebenarnya **sudah pernah membaca teks kalimat ulasan tersebut** selama proses pelatihan! 

Akibatnya:
1. Nilai akurasi dan Macro F1 pada Test Set terlihat sangat tinggi secara tidak wajar (*over-optimistic / memorization*).
2. Ketika model diuji pada ulasan baru di dunia nyata yang belum pernah dipelajari, performanya akan anjlok drastis (*poor generalization*).

---

## 2. Solusi Metodologis: Grouped Stratified Split

Untuk mencegah terjadinya *data leakage*, pembagian data wajib memenuhi dua syarat ketat secara bersamaan:

```text
Aturan Pembagian Data ABSA:
├── 1. Grouped by review_id
│      --> Seluruh pasangan aspek dari review_id yang sama WAJIB berada di set yang sama.
│
└── 2. Stratified by Class Label
       --> Proporsi rasio Negatif (86.2%) vs Positif (13.8%) tetap seimbang di Train, Val, dan Test.
```

---

## 3. Eksekusi Pembagian Data Final (70 / 15 / 15)

Dataset sebanyak 1.205 pasangan aspek-sentimen diisolasi berdasarkan kelompok `review_id` uniknya (total 980 `review_id` unik), kemudian dibagi menggunakan `GroupedStratifiedSplit` dengan `random_state=42`.

Berikut adalah distribusi rincian hasil pembagian data final skripsi kita:

| Set Data | Persentase Target | Jumlah Pasangan Data | Jumlah Review Unik | Negatif ($n$) | Positif ($n$) |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **Training Set** | ~70% | **840 pasangan** | 682 review | 724 | 116 |
| **Validation Set** | ~15% | **180 pasangan** | 148 review | 156 | 24 |
| **Test Set** | ~15% | **185 pasangan** | 150 review | 159 | 26 |
| **Total** | **100%** | **1.205 pasangan** | **980 review** | **1.039** | **166** |

---

## 4. Pembuktian Bebas Leakage (Zero Leakage Check)

Untuk membuktikan secara matematis di hadapan dosen penguji bahwa tidak ada kebocoran data, dilakukan pengujian persimpangan himpunan (*set intersection*) ID ulasan:

$$\text{Set}_{\text{Train}} \cap \text{Set}_{\text{Val}} = \emptyset$$
$$\text{Set}_{\text{Train}} \cap \text{Set}_{\text{Test}} = \emptyset$$
$$\text{Set}_{\text{Val}} \cap \text{Set}_{\text{Test}} = \emptyset$$

Hasil pengujian persimpangan menghasilkan **himpunan kosong ($\emptyset$)**.

Ini membuktikan bahwa:
* 150 review di Test Set benar-benar murni dan belum pernah "dilihat" oleh model selama pelatihan maupun proses tuning hyperparameter.
* Evaluasi performa model pada Test Set dijamin jujur, sah, dan mencerminkan kemampuan generalisasi model sesungguhnya.

---

## Yang Harus Aku Ingat

Jangan pernah mengabaikan bahaya data leakage pada data NLP berpasangan.

Prinsip pembagian data skripsi ini:

> **Grouped Stratified Split by review_id ──► 840 Train / 180 Val / 185 Test ──► Zero Leakage (Persimpangan Himpunan Kosong $\emptyset$).**

Dengan teknik pembagian ini, kita memiliki kepastian ilmiah bahwa hasil evaluasi model kita 100% valid dan bebas dari bias memorisasi.
