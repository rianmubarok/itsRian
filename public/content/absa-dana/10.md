Dalam metodologi penelitian ilmiah sains komputer, ketika kita ingin membuktikan bahwa sebuah metode canggih berbasis Deep Learning (seperti **IndoBERT Fine-Tuning**) memberikan hasil yang bagus, kita **wajib memiliki titik pembanding sepadan yang disebut Model Baseline**.

Tanpa adanya model pembanding baseline yang kuat, nilai Macro F1 sebesar 0.9449 yang diraih IndoBERT tidak memiliki konteks perbandingan—kita tidak bisa membuktikan apakah angka tersebut tergolong luar biasa atau biasa-biasa saja.

Dalam skripsi ini, disepakati bahwa model baseline yang digunakan adalah **Support Vector Machine (SVM)** dengan representasi fitur **TF-IDF (Term Frequency - Inverse Document Frequency)**.

---

## 1. Mengapa Memilih SVM sebagai Baseline?

Support Vector Machine (SVM), khususnya varian `LinearSVC`, adalah salah satu algoritma pembelajaran mesin tradisional paling tangguh dan menjadi tolok ukur standar dalam tugas Klasifikasi Teks (*Text Classification*).

Keunggulan utama SVM untuk klasifikasi teks:
1. **Sangat Efektif pada Data Sparse Berdimensi Tinggi:** Matriks representasi kata (seperti TF-IDF) memiliki ribuan kolom fitur yang sebagian besar bernilai nol. SVM dirancang secara sistematis untuk menangani kondisi ini.
2. **Prinsip Max-Margin Hyperplane:** SVM mencari bidang pemisah (*hyperplane*) dengan jarak marjin terbesar antara dua kelas data, sehingga sangat resisten terhadap *overfitting*.
3. **Efisiensi Komputasi:** Pelatihan SVM berlangsung sangat cepat (hitung detik) dibanding model neural network.

---

## 2. Teknik Prefiks Format Input ABSA pada SVM

Model tradisional seperti SVM tidak memiliki mekanisme *joint input encoding* bawaan seperti token `[SEP]` pada Transformer.

Bagaimana cara memberi tahu SVM bahwa ia harus mengklasifikasikan sentimen terhadap **kategori aspek tertentu** dari sebuah teks ulasan?

Solusinya adalah menyisipkan nama kategori aspek sebagai **prefiks token khusus** di awal teks ulasan:

```text
Format Input SVM Baseline:
"ASPEK_{kategori_aspek} {teks_ulasan_original}"

Contoh Konkret Baris Data:
1. "ASPEK_Transaksi Transfer bank terpotong tapi saldo tidak masuk"
2. "ASPEK_Fitur_dan_layanan Suka banget banyak promo cashback QRIS"
3. "ASPEK_Akun_dan_verifikasi Verifikasi KTP DANA Premium ditolak terus"
```

Dengan teknik penambahan prefiks ini, pengekstrak fitur TF-IDF akan memperlakukan string `ASPEK_Transaksi` atau `ASPEK_Akun_dan_verifikasi` sebagai token unik dalam matriks fitur kata.

---

## 3. Ekstraksi Fitur TF-IDF (Unigram + Bigram)

Teks yang sudah diberi prefiks kemudian dikonversi menjadi matriks numerik menggunakan `TfidfVectorizer` dari pustaka scikit-learn dengan parameter teroptimasi:

```python
from sklearn.feature_extraction.text import TfidfVectorizer

vectorizer = TfidfVectorizer(
    ngram_range=(1, 2),    # Mengambil Unigram (1 kata) dan Bigram (2 kata berdampingan)
    max_features=10000,    # Membatasi matriks pada 10.000 fitur kata teratas
    sublinear_tf=True      # Menggunakan skala logaritmik (1 + log(tf)) untuk meredam frekuensi ekstrem
)
```

Penggunaan **Bigram** (`ngram_range=(1, 2)`) sangat krusial untuk menangkap frasa negasi seperti *"tidak_masuk"*, *"gagal_topup"*, atau *"kurang_bagus"*.

---

## 4. Handling Imbalance: `class_weight='balanced'`

Karena dataset kita imbalanced (86.2% Negatif vs 13.8% Positif), jika SVM dilatih biasa, margin pemisah akan terdorong merugikan kelas minoritas (`Positif`).

Untuk mengatasinya, SVM dikonfigurasi menggunakan parameter bobot otomatis:

```python
from sklearn.svm import LinearSVC

model = LinearSVC(class_weight='balanced', random_state=42)
```

Parameter `class_weight='balanced'` secara otomatis menyesuaikan parameter penalti margin $C$ untuk setiap kelas $k$ secara berbalik nilai dengan frekuensi sampelnya:

$$w_k = \frac{N_{\text{total}}}{n_{\text{classes}} \times n_k}$$

Ini memberikan hukuman penalty yang jauh lebih berat ketika SVM salah mengklasifikasikan ulasan kelas Positif.

---

## 5. Hyperparameter Tuning Parameter $C$ pada Validation Set

Nilai parameter penalti margin $C$ diuji pada **Validation Set (180 sampel)** menggunakan metode *Grid Search* untuk menemukan nilai $C$ terbaik:

| Nilai $C$ | Validation Accuracy | **Validation Macro F1** | Status Hyperparameter |
| :---: | :---: | :---: | :--- |
| $C = 0.01$ | 0.8667 | 0.4645 | Underfitting (Penalti terlalu lemah) |
| $C = 0.10$ | 0.8889 | 0.6982 | Underfitting |
| $C = 0.50$ | 0.9389 | 0.8491 | Cukup Baik |
| **$C = 1.00$** | **0.9500** | **0.8862** | **BEST MODEL (Tuning Optimal)** |
| $C = 2.00$ | 0.9444 | 0.8710 | Mulai Overfitting |
| $C = 5.00$ | 0.9389 | 0.8580 | Overfitting |
| $C = 10.00$ | 0.9389 | 0.8580 | Overfitting |

Nilai **$C = 1.00$** terbukti menghasilkan **Validation Macro F1 tertinggi sebesar 0.8862**.
